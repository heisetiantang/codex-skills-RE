# 账本模板（Ledger Template）

本文件是账本的标准结构。**新建账本、追加日期、重建账本时都按本模板**，保证任何会话接手都能读懂同一份账本。

## 文件位置与命名

- **主账本固定于用户级目录**：默认单用户 `~/.workbuddy/diet-ledger/MEMORY.md`（跨工作区共享，避免账本漂移）
- 多人共用同一台机器：每人一个 `<别名>-MEMORY.md`（别名用初始化画像里的 alias，如 `xiaohua-MEMORY.md`）；账本首行注明 `Alias: xxx`
- 定位顺序：① 用户级 `~/.workbuddy/diet-ledger/` ② 当前工作区 `.workbuddy/memory/`（历史遗留，找到则迁移到用户级）③ 都没有 → 按 SKILL.md"首次使用"建账本，新建落在用户级目录
- 工作区内的 `.workbuddy/memory/MEMORY.md` 迁移后不再作为主账本读写（可留作备份）

## 账本头部模板（固定置于文件最上方）

```markdown
# 饮食营养账本（Diet Tracker）

> 本账本由 diet-tracker skill 维护。结构：头部画像与基准 → 每日记录（**日期递增，最新一天在末尾**）→ 底部实测沉淀库。

## 用户画像（Profile）
- Alias: main（单用户）｜更新日期：2026-04-20
- 性别/年龄/身高/体重：男 / 35 / 175cm / 70kg
- 健康模式：uric-acid（控尿酸）
- 饮食约束：无
- 备注：（如"2026-04 起切换低脂奶"这类关键变更）

## 达标基准（本账本生效）
| 指标 | 区间 | 判定说明 | 来源 |
|------|------|---------|------|
| 蛋白质 | 65~70 g | 区间内绿 / 低红 / 高紫 | 画像生成（例：70kg uric-acid ×0.9~1.0） |
| 脂肪 | ≤50 g | 超即紫 | 画像生成（uric-acid 从严） |
| 热量 | 1500~2200 kcal | 同蛋白三态 | 画像生成（BMR×1.2 维护线微调） |
| 水分 | 2100~2400 ml | >2400 仍算绿 | 画像生成（70kg×30~35） |
| 纤维 | 25~30 g | 同蛋白三态 | 成人通用 |
> 示例值仅为演示占位。实际值必须来自用户画像或中性默认基准（见 SKILL.md"达标基准"节）；"来源"列写清依据。未初始化时用中性默认：蛋白55~75 / 脂肪≤60 / 热量1500~2500 / 水2000~2500 / 纤维25~30，来源标"未初始化(中性默认)"。

## 输出格式速记
- 默认格式B周视图：当周按天、历史周按周均（记N天，**N≥2 才称"周均"，仅1天标"仅1天"**）；列=日期|蛋白|脂肪|热量|水分|纤维|吃了什么(时间)
- 三色字体：绿=达标 / 红=偏低 / 紫=超标；水分>2500ml 仍绿；Markdown 无法显色时改用 HTML 渲染表
- 表后 ≤3 行结论（✅/⚠️）；"吃了什么"列不写饮水，饮水只入水分列
- 详细规则见 diet-tracker SKILL.md 与 report-templates.md

## 每日记录
<!-- 每新增一天，在此复制一节；日期固定递增，最新一节追加到文件末尾（在底部沉淀区之前） -->
### 2026-04-20（一）
- 早（07:00）：食物明细 → 蛋白Xg/脂肪Xg/碳水Xg/热量Xkcal/水Xml/纤维Xg
- 午（13:00）：… 
- 晚（…）：…
- 全天（截至晚餐）：蛋白Xg / 脂肪Xg / 碳水Xg / 热量Xkcal / 水Xml / 纤维Xg
```

## 每日一节的书写规范

- 一行一餐，格式固定：`- 餐别（HH:MM）：吃了什么 → 蛋白Xg/脂肪Xg/碳水Xg/热量Xkcal/水Xml/纤维Xg`
  - 分量不明用 ≈，标"估"；有成分表实拍的标"成分表实测"
  - 饮水不单独成"吃了什么"行，只并入当天水分合计行——但**饮水时段**可另起 `- 饮水：10:00~12:00 共 500ml`（节律分析用，可选）
  - 蛋白目标/达标是全天口径，一餐不必单独判色
- 末尾固定一行**当日累计**（带"截至某餐"状态）：
  `- 全天（截至晚餐）：蛋白Xg / 脂肪Xg / 碳水Xg / 热量Xkcal / 水Xml / 纤维Xg`
  - 若当天还没结束/还有计划，写成"截至X（未计晚餐）"；只有确认吃过的才算
- 日期后缀标星期（一/二/三…），便于周视图切分；跨周自动归周

## 底部：实测沉淀区（本账本已验证食物）

放在文件最后，格式同 nutrition-guide.md，**只放本账本实测/用户确认过的条目**（有成分表实拍或用户明确纠正），并注明验证方式：

```markdown
## 实测沉淀（成分表实拍 / 用户确认）
- 某品牌低脂纯牛奶250ml（成分表实拍）：蛋白8g/脂肪1.5g/碳水12g/96kcal/钙260mg
- 某品牌高蛋白威化60g/包（成分表实拍）：蛋白12g/脂肪22g/碳水24g/340kcal
```

沉淀库随对话增长；它与 SKILL.md 的 nutrition-guide.md 互不覆盖——nutrition-guide 是通用速查，沉淀区是"本用户专属已验证值"，估算时**先查沉淀区、再查 nutrition-guide**。

## 多用户注意

- `~/.workbuddy/diet-ledger/` 下多本账本时，各自维护"画像+基准+沉淀区"，互不混用；收到报餐先确认归属（"记在谁账上？"），不默认 main
- 基准/画像改动（如减脂目标、体重变化、体检新结果）→ 走 SKILL.md"画像/基准更新"流程，改头部表并**标注修改日期**
